# 部署与恢复

## 服务器位置

网站在现有腾讯云 Ubuntu 主机上使用 `/xiangqi/` 路径，沿用主机已配置的 IP TLS 证书。后端只监听 `127.0.0.1:18790`。应用代码位于 `/opt/xiangqi-studio`，数据位于 `/var/lib/xiangqi-studio`，由专用系统用户运行。

`/etc/xiangqi-studio.env` 仅 root 可读，保存 DeepSeek 配置及应用路径，由 systemd 注入后端进程。它不会被传入任何学生代码运行容器。邀请码的服务器原件是数据目录中的 `invitations.json`；本机副本位于受限的应用数据目录，均不提交 Git。

## 发布

`deploy/package.py` 只打包应用源码、前端构建结果和课程模板的允许文件，不包括本机虚拟环境、依赖目录、凭据或真实数据。上传包解压到应用目录后，按需运行 `deploy/install.py`；`--image-only` 更新隔离镜像，`--backend-only` 安装后端及服务。

首次安装由 `deploy/bootstrap.py` 创建专用账号及 Docker。主机 Docker 没有默认网桥和 iptables 修改；运行容器使用 `--network=none`。构建阶段需要从官方源下载工具，并校验 Maven 和 JDT LS 归档。首次下载使用过临时 SSH 代理，正式服务不依赖该隧道。后续构建默认直接下载；需要代理时显式传入 `--build-proxy http://127.0.0.1:<端口>`，并在下载结束后移除临时 Docker 代理配置与隧道。

修改现有 Nginx 时只增加独立的 `xiangqi-studio.conf` include 和 WebSocket map。`deploy/enable_site.py` 会保留修改前配置，执行 `nginx -t`，成功才 reload。不要用整份配置覆盖其他网站的新增路由。

前端更新先 `npm run check` 和 `npm run build`。后端代码更新后重启本服务。镜像更新前先等待本平台的 CI 结束，并安排本平台的运行会话退出；不要重启或清理其他应用服务。

## 检查

```sh
systemctl status xiangqi-studio
journalctl -u xiangqi-studio --since '10 minutes ago'
curl http://127.0.0.1:18790/api/health
docker ps --filter label=xiangqi-studio=session
docker stats --no-stream
df -h /
```

健康接口只说明后端在线。实际运行、语义补全及 CI 还需要镜像、Maven 缓存、JDT 索引和可用资源。连接语义服务后须等到“Java 补全与定义跳转已就绪”。日志中保留真实编译错误，不能以健康接口代替功能验收。

GUI 通过 Xvfb 和 x11vnc 运行，VNC 只监听容器回环地址，经该账号独立 Unix socket 和已登录 WebSocket 转发。源代码编译使用快照，编译过程中继续编辑不会修改正在构建的内容。

索引服务使用每个账号独立、可写的 Maven 缓存；只读镜像内的缓存用于初始化。JDT 首次导入项目会写索引和 Maven 元数据，不能将这部分错误配置为只读。

## 数据与恢复

需要保留的数据包括 `state.sqlite3`、`groups` 下的 Git 仓库，以及 `runtime/<账号>/data` 中的游戏存档。`workspaces` 是个人当前草稿的磁盘镜像，Git 中保存各账号的草稿引用和候选引用。索引缓存和运行源码快照可以重新生成。

数据库备份使用 SQLite backup API，不能在写入时只复制主数据库而漏掉 WAL。先取得一致的数据库副本，再归档 Git 对象与引用及游戏文件。备份和邀请码均按私人材料保存；源代码 GitHub 仓库不能替代运行数据备份。

服务重启后，未完成的 CI 会标记为失败并保留候选，用户可重新校验。它不会把中断任务记为通过，也不会据此更新共同版本。

恢复代码发布时使用 Git 提交和此前验证过的镜像；恢复用户数据时先停止本应用写入，保留当前数据目录的可恢复副本，再恢复一致的数据库和 Git 仓库。恢复 Nginx 仅移除本应用的 include/map，保留其他网站当前配置。

## 首轮资源约束

两个账号各运行一个 GUI 和一个语义服务，共四个容器；CI 另外串行运行。运行镜像不能通过用户项目文件获得主机网络或其他账号的数据。Docker 日志按 5 MiB × 2 轮转。

服务器初次安装前只有约 3.8 GiB 可用空间，因此没有额外安装一套主机 JDK，也没有下载浏览器到服务器。后续大规模添加依赖、资源或增加并发前，应重新确认空间和内存。不要把“容器有内存上限”当成磁盘配额；长期积累的版本和游戏数据需要按实际用量维护。
